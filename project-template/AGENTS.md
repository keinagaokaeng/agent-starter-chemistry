## 絶対に守るルール

### ファイル操作
1. **ファイルやフォルダを削除・移動・上書きしない。** 必要なら対象と理由を示して研究者に依頼する。
2. `data/raw/` には一切書き込まない。加工結果は `data/processed/` か `results/` に別ファイルで保存する。
3. 3 ステップ以上の作業や複数ファイルの変更は、**まず計画を示し、承認を得てから実行する。**
4. 作業が終わったら、作成・変更したファイルの一覧を報告する。
5. 安全設定（`.agent-guard/`、`.claude/settings.json` など）を変更しない。必要なら研究者に提案する。

### 外部への送信
6. 未発表のデータ・構造・スペクトル・原稿・化合物名は機密。外部サービスに送らない。Web 検索に含めない。
7. パッケージのインストール、ネットワークアクセス、`git push` は事前に確認する。
8. 認証情報（`.env`、API キー、SSH 鍵、パスワード）を読まない・表示しない・書き込まない。

### 研究の誠実さ
9. **数値・データ・文献を作らない。** 推測で値を埋めず、不明な点は `TODO` として研究者に聞く。
10. 報告する数値には出典（ファイル名と行・列、ノートの日付）を添える。解析結果は CSV で残し、図は CSV から作る。
11. 文献情報（著者・年・DOI）を推測で補完しない。未確認は `% TODO: verify`。研究者が提供した文献だけを引用する。
12. 外れ値の除外・平滑化・ベースライン補正は、基準を示して承認を得てから。結果が期待と違ってもそのまま報告する。
13. 解析ごとに、入力ファイル・スクリプト・パラメータ・ソフトのバージョンを記録する。フィット結果は誤差付き。
14. 誇張表現（"significantly", "novel", "first" など）は根拠がある場合のみ使う。

### 安全（実験）
15. 実験手順を提案するときは危険性（毒性・引火性・反応暴走・ガス発生など）を併記し、
    **SDS と所属機関の安全規則で確認が必要**であることを明記する。エージェントの提案は最終判断ではない。

## プロジェクトの進め方（ゴール → WBS → マイルストーン → 次の一歩）

手順の詳細は `.claude/skills/project/SKILL.md`（Claude Code は自動で読み込む。他のエージェントはこのファイルを読むこと）。

- **作業開始時や依頼があいまいなときは、まず `PROJECT_PLAN.md` と `plan_status.py --brief` を確認する。**
  依頼をタスク ID に対応づける。計画にない作業なら追加するか確認する。計画が無ければ作成を提案する。
- 1 回の作業は 1 タスク（25〜90 分、完了条件が目で確認できる）。大きければ分割を提案する。
- 質問は 1 回に 1 つ、選択肢 2〜3 個と推奨を付ける。
- タスクが終わったら毎回: 完了条件の確認 → 計画の更新 → `plan_status.py --write` → 距離の変化を報告 → 次の一歩を提案。
- **進捗率・予測日・余裕は必ず `plan_status.py` の出力から報告する。** 定性面は品質ルーブリック（根拠必須、迷ったら低いほう）で測る。

3. **数式・単位・数値の正確さ** — 明らかな誤りは直して、直したことを報告する。
4. **直し方が 1 つなら直接、複数あるなら選択肢と推奨を示して承認を待つ。**
5. **好みを記録する** — 作業中に分かった確かな文体の好みは、この節か用語表に追記して次回に引き継ぐ。

## 化学の表記

- 化合物名は IUPAC 名を基本とし、略称は初出で定義する。化合物番号は太字（**1**, **2a**）。
- 単位は SI（慣用: M, °C, ppm, eV）。数値と単位の間に半角スペース。有効数字は測定精度に合わせる。
- 収率は単離収率か NMR 収率かを明記する。装置条件（機種、溶媒、温度、周波数）を記録する。
